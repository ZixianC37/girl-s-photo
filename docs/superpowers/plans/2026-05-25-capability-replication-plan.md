# 写真产品研发能力复制系统 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建一个将资深高手的爆款研发能力复制给新人的系统，通过可行性调研验证拆解方法后，逐步实现工作流引导+知识库+归因分析的闭环。

**Architecture:** 三层能力模型（信息层/决策层/审美层）作为后台架构，工作流引导作为使用者界面，知识引擎和归因引擎作为数据支撑。数据闭环驱动系统自我增强。

**Tech Stack:** 待可行性调研后确定（候选：飞书多维表格扩展 / 独立 Web 工具）

**Spec:** `docs/superpowers/specs/2026-05-25-photo-product-rd-capability-replication-design.md`

---

## 计划结构

本计划分为两个大阶段：

- **阶段 0：可行性调研**（约 2-3 周）— 验证核心假设后再决定是否投入开发
- **阶段 1：MVP 实现**（约 4-6 周）— 基于调研结论构建最小可行产品

阶段 1 的具体实现细节将根据阶段 0 的调研结论来细化。本计划中阶段 1 的任务是框架性的，待调研完成后需更新。

> **硬门控：不允许在 Task 0.5 产出 Go 或条件性 Go 结论之前开始任何 Task 1.x 的工作。** 阶段 1 的技术栈、文件结构、任务粒度均依赖调研结论确定。

## 设计原则检查清单（阶段 1 所有任务必须遵守）

来自 spec 的四条设计原则，在实现阶段 1 的每个组件时必须逐一检查：

- [ ] **架构-界面分离**：三层能力模型是后台架构，使用者界面是自然的工作流助手（不暴露内部术语）
- [ ] **置信度标注**：每条知识条目包含来源样本量和验证状态字段
- [ ] **时效性管理**：每条知识条目包含时效标签和最后验证时间字段
- [ ] **记录为主评分为辅**：成长追踪以存档为主，不引入复杂评分算法

```
# 可行性调研计划

## 调研目标
验证三个核心假设：
1. 隐性知识可提取性：资深高手能否清晰表达其决策逻辑和隐性知识
2. 数据基础充分性：飞书多维表格中的产品数据是否足以支撑知识库和归因分析
3. 能力差距可量化性：高手与新人在同一任务上的差异是否可以被结构化识别

## 调研方法
### 假设1验证：决策回溯访谈
- 选择 1 个参考对象
- 拿 1 个爆款产品和 1 个非爆款产品
- 回溯访谈：记录每个关键决策点的判断依据
- 评估：参考对象能清晰表达的决策点占总决策点的比例

### 假设2验证：飞书数据审计
- 导出飞书多维表格中的产品数据样本
- 评估字段完整性、数据质量、时间覆盖范围
- 识别缺失字段和数据缺口

### 假设3验证：对比实验
- 选择 1 个参考对象 + 1 个培养对象
- 给同一个任务（如"策划一个夏季写真主题"）
- 对比全过程的决策差异
- 评估差距是否可被结构化描述

## 调研产出
- 决策回溯访谈记录（含决策点清单和可表达性评估）
- 飞书数据审计报告（字段完整性、数据缺口）
- 对比实验报告（差距类型和结构化程度评估）
- 可行性结论和建议（Go/No-Go/条件性 Go）

## 时间安排
- 第 1 周：飞书数据审计 + 参考对象招募沟通
- 第 2 周：决策回溯访谈 + 对比实验
- 第 3 周：分析结论 + 决策会议
```

基于 7 阶段 SOP，为回溯访谈定制问题框架：

```
# 决策回溯访谈提纲

## 访谈准备
- 选择 1 个爆款产品（有明确成功数据的产品）
- 选择 1 个表现一般的产品（作为对比）
- 准备产品相关的所有历史资料（方案文档、成品、销售数据）

## 访谈流程（每个产品约 90 分钟）

### 第一部分：整体回溯（20 分钟）
1. 请简要描述这个产品从构思到上线的全过程
2. 这个产品最初的灵感/想法是怎么来的？
3. 你当时对这个产品的期望是什么？实际结果如何？

### 第二部分：逐阶段决策回溯（50 分钟）
针对 7 个阶段，每个阶段询问：
1. 在这个阶段，你做了什么关键决策？
2. 你当时考虑了哪些因素？（列出所有影响因素）
3. 你排除了哪些备选方案？为什么排除？
4. 如果让你现在重新做，你会做不同的选择吗？为什么？
5. 这个决策中，有哪些是你"感觉"应该这样的，但很难说清原因的？

### 第三部分：隐性知识探索（20 分钟）
1. 在整个过程中，有没有某些时刻你觉得"就是知道该这样做"？
2. 这种"知道"来自什么？（过去的经验？某种直觉？看到什么信号？）
3. 如果要教一个新人做出和你一样的决策，你觉得最难传达的是什么？
4. 你觉得新人做这个产品，最可能在哪些地方出错？

## 记录规范
- 每个决策点记录为：阶段 → 决策内容 → 考虑因素 → 排除方案 → 决策理由 → 可表达性评分（1-5）
- 可表达性评分标准：
  - 5: 能清晰说明原因和逻辑
  - 4: 能说明大部分原因，部分依赖感觉
  - 3: 能说明一些原因，但很多凭直觉
  - 2: 主要是直觉，只能说出一部分原因
  - 1: 完全凭直觉，无法解释原因
```

```
# 对比实验方案

## 实验目的
识别参考对象与培养对象在产品研发过程中的具体差距，评估差距是否可被结构化描述。

## 实验设计
- 参考对象：1 人（与访谈同一人）
- 培养对象：1 人
- 任务：独立完成"策划一个夏季写真主题产品"（从阶段 1 到阶段 2 的输出）
- 任务内容：
  1. 收集并分析当前夏季风格趋势
  2. 提出 2-3 个主题方案
  3. 选择一个主题细化，输出完整的产品定义文档

## 过程记录
对每位参与者，在关键节点记录：
- 考虑了哪些信息源
- 做了什么决策
- 考虑因素和排除方案
- 花费的时间
- 遇到的困惑/卡点
- 最终产出

## 对比维度
1. 信息获取：两人获取的信息量、信息源数量、信息质量差异
2. 决策过程：决策节点覆盖度、考虑因素全面性、备选方案数量
3. 产出质量：最终方案由参考对象盲评打分
4. 过程效率：各步骤耗时对比
5. 卡点差异：各自遇到的困难和解决方式
```
