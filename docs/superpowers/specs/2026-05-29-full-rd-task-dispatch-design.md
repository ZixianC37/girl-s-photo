# 产品研发任务分发完整设计

## 目标

实现产品研发任务从创建到完成的完整链路：运营在管理后台创建任务 → 钉钉群发送互动卡片 → 参与者确认接单 → 上传交付物 → 全部完成后汇总通知创建者。

## 前置条件：钉钉开放平台配置

### 步骤 1：创建企业内部应用

1. 登录 [钉钉开放平台](https://open-dev.dingtalk.com)
2. 进入「应用开发」→「企业内部开发」→「创建应用」
3. 填写应用名称（如「中台任务助手」），选择「H5微应用」
4. 创建后获得 **AppKey** 和 **AppSecret**

### 步骤 2：开通机器人能力

1. 进入应用 →「应用能力」→「机器人」
2. 开启机器人能力
3. 获得 **RobotCode**（即 AppKey 或自定义的机器人编码）
4. 配置消息接收模式为「HTTP 模式」

### 步骤 3：配置互动卡片

1. 进入「开放平台」→「卡片搭建器」
2. 创建卡片模板，定义：
   - 卡片标题区
   - Markdown 内容区
   - 按钮交互区
3. 记录 **Card Template ID**
4. 配置按钮回调：点击按钮时向中台服务器发送 HTTP 请求

### 步骤 4：配置事件订阅

1. 进入应用 →「事件与回调」→「事件订阅」
2. 设置回调 URL：`https://your-server/webhook/dingtalk/callback`
3. 开启卡片交互事件订阅

### 步骤 5：部署机器人到群

1. 在目标钉钉群中，点击「群设置」→「机器人」→「添加机器人」
2. 选择刚创建的应用机器人
3. 记录群的 **openConversationId**（即 group_id）

### 环境变量

配置完成后，将以下信息写入 `.env`：

```
DINGTALK_APP_KEY=你的AppKey
DINGTALK_APP_SECRET=你的AppSecret
DINGTALK_ROBOT_CODE=你的RobotCode
```

## 完整用户流程

```
1. 运营在管理后台「产品研发」页面创建主任务
   → 填写标题、描述
   → 添加子任务：标题、负责人（逗号分隔名字）、目标群、截止时间、交付物要求

2. 系统为每个子任务：
   → 创建 task_route + task_instance
   → 调用钉钉 API 发送互动卡片到目标群

3. 群内参与者看到卡片，点击「确认接单」
   → 钉钉发送回调到中台
   → 中台更新 participant 状态为 confirmed
   → 更新卡片为「已确认」状态

4. 参与者在机器人私聊中发送文件/图片
   → 钉钉发送消息回调到中台
   → 中台匹配参与者 → 记录文件 → 回复确认消息
   → 当交付物数量满足要求时，更新状态为 submitted

5. 所有参与者完成后：
   → task_instance 状态更新为 completed
   → 中台向创建者发送汇总通知（群卡片或私聊）

6. 所有子任务完成后：
   → rd_task 状态更新为 completed
```

## 数据字段

### 主任务（rd_task）

| 字段 | 必填 | 说明 |
|------|------|------|
| 标题 | 是 | 如"春季新品研发" |
| 描述 | 否 | 补充说明 |

### 子任务（rd_sub_task）

| 字段 | 必填 | 说明 |
|------|------|------|
| 标题 | 是 | 如"样片拍摄" |
| 描述 | 否 | 子任务详细说明 |
| 负责人 | 是 | 逗号分隔的用户标识（MVP 阶段手动输入） |
| 目标群 | 是 | 钉钉群 openConversationId |
| 截止时间 | 否 | 可选截止日期 |
| 交付物 | 否 | 交付物要求列表（名称 + 数量） |

## 私聊文件收集流程

```
用户在私聊中发送文件/图片给机器人
  │
  ├── 查询 task_participant 表
  │   WHERE platform_user_id = ? AND status IN ('confirmed', 'submitted')
  │
  ├── 只有 1 个活跃任务 → 自动归属
  │   → 记录文件到 file_record
  │   → 回复："已收到「xxx.pdf」（1/3），请继续发送"
  │
  ├── 有多个活跃任务 → 发送选择卡片
  │   "你有多个待提交任务，请选择："
  │   [样片拍摄] [色彩方案] [后期修图]
  │
  └── 没有活跃任务 → 回复："当前没有待处理的任务"
```

## 汇总通知

所有子任务完成时，向任务创建者发送汇总卡片：

```
┌─────────────────────────────────────┐

│  ─────────────────────               │

```

## 后端需要实现的功能

### 1. 钉钉 API 对接

- **获取 access_token**：POST /v1.0/oauth2/accessToken（已有）
- **发送群卡片**：POST /v1.0/card/instances（已有）
- **更新群卡片**：PUT /v1.0/card/instances（已有）
- **发送私聊消息**：POST /v1.0/robot/oToMessages/batchSend（已有）
- **下载文件**：POST /v1.0/robot/messageFiles/download（已有）
- **接收卡片回调**：POST /webhook/dingtalk/callback（已有）
- **接收消息回调**（私聊文件）：需新增事件订阅处理

### 2. Handler 业务逻辑

- `parse_event()`：从合成事件提取子任务数据
- `build_card()`：根据状态构建不同卡片内容
- `handle_callback('confirm')`：处理确认接单
- `handle_callback('file_received')`：处理文件接收
- `get_reminder_rules()`：催办规则

### 3. 私聊路由

- 接收钉钉机器人私聊消息回调
- 匹配参与者 → 归属文件 → 记录进度

### 4. 汇总通知

- 子任务全部完成时检查
- 向创建者发送汇总卡片
