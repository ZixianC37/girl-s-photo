# 产品指标体系设计文档

> **版本**: v1.2
> **日期**: 2026-06-05
> **作者**: 产品经理 + AI 多专家协作
> **状态**: 待评审

## 1. 背景与目标

### 1.1 业务背景

也许文化是一家写真摄影连锁企业，旗下三大品牌（麦芽纪、麦芽岛、甜熊）、7+ 家营业中门店、1000+ 产品方案。公司已有四指标体系（点拍/客资/成交/点赞），但缺乏**产品粒度**的经营分析能力。

当前痛点：
- 无法快速知道哪些产品「客资高但点拍低」（引流好但门店没推）
- 无法快速知道哪些产品「客资低但点拍高」（产品好但营销没跟上）
- 无法衡量「30日上新产品占门店成交的多少比例」
- 缺乏产品全生命周期的健康度评价体系
- 新品跟踪表有运营发布数据，但没有和门店成交数据打通

### 1.2 设计目标

1. **首要服务对象**：产品经理（单品粒度指标）
2. **核心管理目标**：让产品表现「看得见」，先有全局监控能力
3. **升级方向**：逐步叠加诊断能力（异常识别）和闭环追踪（决策效果评估）

### 1.3 约束条件

- 数据基础：飞书多维表，149 张表，产品级公式已有部分（执行output 表的近30天拍摄量）
- 数据缺口：客资数据目前无法归因到产品维度
- 不给门店加活：门店端只做现有流程的自然数据沉淀
- 现有资产复用：研发部排行榜已有点拍排名等数据，不重复建设

## 2. 指标体系总架构

```
┌─────────────────────────────────────────────────┐
│  L4 闭环层：决策追踪                              │
│  记录每一次上新/下架/调整决策，追踪后续效果           │
├─────────────────────────────────────────────────┤
│  L3 诊断层：异常识别 + 行动建议                     │
│  自动识别异常产品，触发预警和推荐动作                 │
├─────────────────────────────────────────────────┤
│  L2 健康层：产品健康度分析                          │
│  三维诊断 + 引流力（待补全）                        │
│  转化力×营收力×生命力 + 引流力(Phase 3)              │
├─────────────────────────────────────────────────┤
│  L1 经营层：基础经营指标                            │
│  点拍/成交/客资/点赞 + 30日新品占比                  │
└─────────────────────────────────────────────────┘
```

### 核心设计原则

1. **数据源分离**：「自动采集」vs「需补录」，自动采集的先上，补录的逐步迭代
2. **来源归因分离**：「来源产品」（客户被什么吸引来）和「成交产品」（客户实际拍了什么）是两条独立的评价管线
3. **产品粒度**：所有指标落到单品（方案名称）级别，可上卷到门店/品牌/一级分类
4. **时间维度**：30天滚动窗口为主，辅以月环比和生命周期阶段

### 四大评价维度（引流力于 Phase 3 补齐，Phase 1-2 为三维模型）

| 维度 | 问答 | 数据来源 | 可用阶段 |
|------|------|----------|----------|
| **引流力** | 这个产品能吸引客户来吗？ | 客资归因（来源产品侧）+ 公域互动数据 | Phase 3 |
| **转化力** | 客户到店后会选这个产品拍吗？ | 日拍摄清单 → 拍摄风格点拍统计 | Phase 2 ✅ |
| **营收力** | 这个产品能带来多少收入？ | 日拍摄清单 → 拍摄金额聚合 | Phase 2 ✅ |
| **生命力** | 这个产品处于生命周期的哪个阶段？ | 上新时间 + 状态 + 点拍趋势 | Phase 2 ⚠️ |

四个维度的交叉诊断（引流力相关的两条在 Phase 3 解锁）：
- **引流力强 + 转化力弱** = 客资高、点拍低 → 公域内容好但门店没推（Phase 3）
- **引流力弱 + 转化力强** = 客资低、点拍高 → 产品本身好但营销没跟上（Phase 3）
- **转化力强 + 营收力弱** = 点拍高、成交低 → 拍了但客单价低或选片环节问题（Phase 2 ✅）
- **生命力低 + 转化力强** = 老品但仍热门 → 经典款，值得保留（Phase 2 ✅）
- **生命力高 + 转化力低** = 新品但无人拍 → 可能选品失误或上架时机不对（Phase 2 ✅）
- **三维全低** = 低效产品 → 评估下架释放场景资源（Phase 2 ✅）

## 3. L1 经营层 — 基础经营指标

### 3.1 产品级核心指标

| 指标名 | 计算方式 | 数据来源 | 时间维度 |
|--------|----------|----------|----------|
| 月点拍数 | 日拍摄清单按「拍摄风格」分组计数 | 各门店日拍摄清单 | 月度/30天滚动 |
| 月成交金额 | 日拍摄清单按「拍摄风格」分组求和「本次拍摄金额」 | 各门店日拍摄清单 | 月度 |
| 平均客单价 | 月成交金额 ÷ 月点拍数 | 计算值 | 月度 |
| 当前状态 | 执行output.小程序端 | 执行output | 快照 |
| 生命周期天数 | 今天 − 上新时间 | 执行output.上新时间 | 实时 |

### 3.2 门店级汇总指标

| 指标名 | 计算方式 | 说明 |
|--------|----------|------|
| 门店月点拍总量 | 门店所有拍摄风格计数求和 | 门店经营规模 |
| 门店月成交总额 | 门店所有拍摄金额求和 | 门店营收 |
| **30日新品成交占比** | 上新时间在30天内的产品成交额 ÷ 门店总成交额 | 新品对营收的贡献 |
| 30日新品点拍占比 | 上新时间在30天内的产品点拍数 ÷ 门店总点拍数 | 新品渗透率 |
| 活跃产品数 | 当月有点拍记录的产品去重数 | 产品丰富度 |
| 场景利用率 | 有拍摄记录的场景数 ÷ 总场景数 | 资源效率 |

### 3.3 与现有资产的关系

| 内容 | 状态 |
|------|------|
| 产品级核心指标（点拍、成交、客单价） | 新增，研发部排行榜可能没有金额维度 |
| 门店级汇总（30日新品占比、场景利用率） | 新增，排行榜是产品维度不是门店维度 |
| 点拍排行 / 僵尸产品 / 同类排名 | 已有，直接引用研发部排行榜 |

### 3.4 数据可行性

```
日拍摄清单.拍摄风格 ──→ 分组计数 ──→ 产品月点拍数 ✅
日拍摄清单.拍摄风格 ──→ 分组求和(本次拍摄金额) ──→ 产品月成交金额 ✅
执行output.上新时间 ──→ 过滤30天内 ──→ 30日新品集合 ✅
两者交叉 ──→ 30日新品成交占比 ✅
```

**前提条件**：需确认日拍摄清单的「拍摄风格」选项和执行output的「方案名称」选项是否一一对应。如果不完全一致，需建立映射关系。

### 3.5 数据映射校验（Phase 0 — 所有后续工作的前置条件）

在实施 L1 之前，必须先完成以下校验：

1. **抽样校验**：从每个门店的日拍摄清单中随机抽取 50 条记录，将其「拍摄风格」值与执行output的「方案名称」进行交叉比对
2. **映射率评估**：
   - 映射率 ≥ 90%：直接进入 Phase 1
   - 映射率 80%-90%：建立映射对照表后进入 Phase 1，增加复验检查点
   - 映射率 < 80%：阻塞 Phase 1，需先修复数据结构
3. **字段完整性校验**：
   - 确认执行output.上新时间字段存在且 ≥ 95% 的已上架产品有非空值
   - 检查上新时间分布是否合理（不应全部集中在最近几个月，否则可能是数据迁移问题）
4. **输出物**：一张「拍摄风格 ↔ 方案名称映射对照表」（存入飞书多维表），后续所有聚合计算基于此映射

### 3.6 数据新鲜度与查询维度

**数据新鲜度**：

| 指标 | 数据来源 | 更新频率 | 可见延迟 |
|------|----------|----------|----------|
| 月点拍数 | 日拍摄清单 | 门店录入后实时 | T+1（门店当日录入，次日可见） |
| 月成交金额 | 日拍摄清单 | 门店录入后实时 | T+1 |
| 30日新品占比 | 执行output.上新时间 | 实时 | 实时 |
| 场景利用率 | 执行output 影棚字段 | 实时 | 实时 |
| 月环比趋势 | 需月度快照或仪表盘筛选 | 每月初 | M+1（次月初可见） |

**维度与筛选矩阵**：

| 指标 ↓ \ 维度 → | 门店 | 品牌 | 一级分类 | 生命周期阶段 | 时间（月） |
|-----------------|------|------|----------|-------------|-----------|
| 月点拍数 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 月成交金额 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 客单价 | ✅ | ✅ | ✅ | — | ✅ |
| 30日新品占比 | ✅（门店级） | ✅ | — | — | ✅ |
| 场景利用率 | ✅（门店级） | — | — | — | ✅ |
| 活跃产品数 | ✅ | ✅ | ✅ | — | ✅ |

上卷路径：产品 → 一级分类 → 品牌 → 全公司

## 4. L2 健康层 — 产品健康度分析

### 4.1 健康度评分模型

每个产品在每个维度上计算**相对分数**——取该产品在其「一级分类」内的排名百分位，映射为 1-5 分。

> **注意**：由于客资数据目前无法归因到产品（见 §7.3），**引流力维度在第一、二阶段暂不可用**。L2 初期为**三维模型**（转化力×营收力×生命力），引流力在第三阶段补齐后升级为四维。

| 维度 | 衡量什么 | 数据源 | 评分依据 | 可用阶段 |
|------|----------|--------|----------|----------|
| 转化力 | 到店后客户选择率 | 日拍摄清单点拍数 | 月点拍数，分类内百分位 | Phase 2 ✅ |
| 营收力 | 创收能力 | 日拍摄清单成交金额 | 月成交金额，分类内百分位 | Phase 2 ✅ |
| 生命力 | 产品处于哪个阶段 | 上新时间 + 点拍趋势 | 生命周期天数 + 月环比趋势 | Phase 2 ⚠️ |
| 引流力 | 吸引客户的能力 | 客资归因（来源产品侧）+ 公域互动数据 | 来源产品客资数，分类内百分位 | Phase 3 ❌ |

**引流力替代方案（Phase 2 过渡期）**：可用「运营发布数」（新品追踪表.链接字段非空数量）作为引流力的弱信号替代指标。虽然不精确，但能提供方向性参考。

### 4.2 健康度交叉诊断矩阵

| 象限 | 表现 | 诊断 | 典型动作 |
|------|------|------|----------|
| 引流↑ 转化↓ | 客资高、点拍低 | 公域内容好，门店没推到位 | 联系门店加强引导、更新样品展示 |
| 引流↓ 转化↑ | 客资低、点拍高 | 产品本身好，但营销没跟上 | 运营加大该品内容投放 |
| 转化↑ 营收↓ | 点拍高、成交低 | 客户拍了但客单价低 | 检查是否被低价品引流、优化选片引导 |
| 生命力↓ 转化↑ | 老品但仍热门 | 经典款，值得保留 | 维持上架，无需干预 |
| 生命力↑ 转化↓ | 新品但无人拍 | 可能选品失误或上架时机不对 | 观察1-2周，持续低迷则考虑下架 |
| 四维全低 | 各维度都低于平均 | 低效产品 | 评估是否下架释放场景资源 |

### 4.3 趋势指标

**时间口径说明**：本体系采用**自然月**作为趋势计算的基本周期（与日拍摄清单的录入节奏一致），而非30天滚动窗口。滚动窗口仅用于「近N天拍摄量」这类即时查询。

| 指标 | 计算方式 | 用途 |
|------|----------|------|
| 点拍月环比 | 本自然月点拍 ÷ 上自然月点拍 | 短期趋势 |
| 同类排名变化 | 本月排名 − 上月排名 | 竞争力变化 |
| 生命周期阶段 | 上新天数映射：0-30 爆发期 / 31-90 稳定期 / 91-180 衰退期 / 180+ 长尾期 | 阶段判断 |

**月环比的数据来源**：执行output 表中已有公式字段计算近30天拍摄量。月环比需要「本月快照」和「上月快照」两张视图，可通过飞书仪表盘的筛选条件实现（按月份筛选），或新增「产品月度快照」表自动记录（Phase 2 评估）。

### 4.4 数据可行性

| 指标 | 可行性 | 说明 |
|------|--------|------|
| 转化力（点拍） | ✅ 立即可用 | 日拍摄清单按拍摄风格计数 |
| 营收力（成交金额） | ✅ 立即可用 | 日拍摄清单按拍摄风格求和金额 |
| 生命力（时间+趋势） | ⚠️ 部分可用 | 上新时间有，趋势需月度环比（多维表公式可做） |
| 引流力（客资归因） | ❌ 需补数据 | 客资数据目前无法归因到产品 |

**周度 vs 月度趋势**：周度聚合在多维表公式中较难实现，建议用月度环比代替。如确实需要周度，可新增「产品月度快照」表。

## 5. L3 诊断层 — 异常识别与行动建议

### 5.1 异常识别规则

| 规则编号 | 触发条件 | 异常类型 | 严重度 |
|---------|---------|---------|--------|
| R1 | 已上架产品，近30天点拍数 = 0 | 僵尸产品 | 🟡 中 |
| R2 | 新品上架30天内，点拍数低于同分类平均的50% | 新品遇冷 | 🟠 高 |

> **R2 阈值说明**：「50%」为初始经验值，上线后根据新品实际点拍分布调整。定义「遇冷」需结合门店数——单门店低点拍可能是正常的（该门店没推），多门店都低才需要重点排查。
| R3 | 连续2个月点拍下降（月环比<1） | 衰退预警 | 🟡 中 |
| R4 | 点拍数高于平均但成交金额低于平均 | 高拍低收 | 🟡 中 |
| R5 | 客资高（来源产品）但对应门店点拍低 | 引流浪费 | 🔴 高 |
| R6 | 上新90天后，点拍仍在分类前30% | 经典款识别 | 🟢 正向 |
| R7 | 某场景关联产品 > 10个，但点拍集中度（按点拍数排名前3的产品占该场景总点拍数的比例）> 80% | 场景拥堵 | 🟠 高 |

> **R7 阈值说明**：「> 10个产品」和「TOP3 占比 > 80%」为初始经验值，上线后根据实际数据分布调整。场景-产品关联关系来自执行output表的影棚字段。

### 5.2 行动建议映射

| 异常类型 | 推荐行动 | 责任人 |
|----------|----------|--------|
| R1 僵尸产品 | 评估下架，释放场景资源 | 产品经理 |
| R2 新品遇冷 | 排查：样片展示？门店引导？定价？ | 产品经理 + 店长 |
| R3 衰退预警 | 准备替代新品，规划下架时间线 | 产品经理 |
| R4 高拍低收 | 优化选片引导，检查套餐搭配 | 门店 |
| R5 引流浪费 | 门店加强该品展示和话术 | 店长 + 运营 |
| R6 经典款识别 | 标记为常驻款，优先保障场景资源 | 产品经理 |
| R7 场景拥堵 | 疏导低效产品到替代场景 | 产品经理 |

### 5.3 呈现方式

在仪表盘中增加异常面板，按严重度分组展示异常产品列表，每条异常附带诊断说明和推荐动作。

## 6. L4 闭环层 — 决策追踪

### 6.1 产品决策日志表（新增飞书多维表）

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 方案名称 | 双向关联 → 执行output | 哪个产品 |
| 决策类型 | 单选：上新 / 下架 / 调整 / 场景迁移 / 价格调整 | 做了什么 |
| 决策日期 | 日期 | 什么时候做的 |
| 决策原因 | 文本 | 为什么做（关联 L3 异常编号） |
| 预期效果 | 文本 | 做了之后期望什么变化 |
| 决策人 | 单选 | 谁做的决策 |
| 决策后30天点拍 | 公式 | 自动追踪 |
| 决策后30天成交 | 公式 | 自动追踪 |
| 效果评价 | 单选：超预期 / 符合预期 / 低于预期 / 失败 | 后续复盘 |

### 6.2 闭环流程

```
L3 异常触发 → 记录到决策日志 → 30天后自动拉数据 → 人工评价效果 → 沉淀经验
     │                                                          │
     └──────────── 下次遇到同类异常时参考 ──────────────────────┘
```

### 6.3 管理价值

| 管理目标 | 实现方式 |
|----------|----------|
| 决策有据可查 | 每次上新/下架都有记录，不是拍脑袋 |
| 团队学习 | 积累判断经验 |
| 效果量化 | 能回答「上月5次下架决策效果如何」 |
| 数据驱动文化 | 逐步替代凭感觉做决策 |

## 7. 各层与现有表格的适配关系

### 7.1 涉及的现有飞书多维表

| 指标层 | 涉及的现有表 | 用途 |
|--------|-------------|------|
| L1 经营层 | 日拍摄清单（8张，每门店一张） | 点拍数、成交金额、拍摄风格 |
| L1 经营层 | 执行output（44字段） | 产品主表、上新时间、状态、场景、近30天拍摄量 |
| L1 经营层 | 门店每日拍摄统计总表新 | 门店级拍摄风格汇总 |
| L2 健康层 | 新品跟踪表（25字段） | 运营发布数据、月度拍摄量 |
| L2 健康层 | 新品追踪（12字段） | 风格状态评级、发布人 |
| L2 健康层 | 产品包查询（29字段） | 产品详情、成本、分类 |
| L1 经营层 | 研发部排行榜 | 点拍排名、同类对比（已有，引用） |

### 7.2 需要新增的内容

| 层级 | 新增内容 | 类型 | 优先级 |
|------|----------|------|--------|

### 7.3 关键数据缺口

| 缺口 | 影响 | 解决方案 |
|------|------|----------|
| 客资无法归因到产品 | L2 引流力维度暂时无法计算 | 第三阶段通过运营发布数据反推 |

## 9. 多专家评审意见汇总

### 📊 数据分析专家

- 四维模型的评分方法（分类内百分位映射）合理，能有效消除不同分类间的量级差异
- 需特别注意数据口径：执行output 里的「近三十天拍摄量」是公式计算值，和日拍摄清单手动统计可能有差异
- 30日新品占比的「30日」用上新时间判断，但需明确是「上新时间距今<30天」还是「确认上新日期距今<30天」

### 🏪 门店运营专家

- L1 不增加门店录入负担 ✅
- L3 的异常面板如果有门店维度的，希望能推送给对应店长
- 客资归因（第三阶段）如果需要在门店端录入「来源产品」，建议用下拉选择而非手填，且设为非必填

### 📦 产品研发专家

- 四维模型和8阶段研发流程可以很好对应：引流力对应「运营安排→正式上新」阶段，转化力对应「正式上新→门店执行」阶段
- 生命周期阶段的划分（0-30/31-90/91-180/180+）和现有「3个月新品跟踪」的节奏一致
- 建议增加「研发人维度」：同一研发人的产品平均表现如何，辅助研发人员评估

### 🔧 飞书多维表技术专家

- L1 的产品级聚合：多维表的仪表盘「统计」视图可以原生支持按字段分组计数/求和，部分指标可以直接在仪表盘实现
- 月度快照表如果需要自动创建，需要飞书自动化（工作流）或飞书应用
- 产品决策日志表结构简单，多维表原生能力完全可以实现
- 需要评估：执行output 表已有 44 个字段，新增关联是否会影响性能

## 10. 附录：术语表

| 术语 | 定义 |
|------|------|
| 来源产品 | 客户通过公域内容（小红书等）被吸引来的那个产品 |
| 成交产品 | 客户到店后实际选择拍摄的产品 |
| 点拍 / 点拍数 | 客户实际拍摄某产品的次数（本文档统一使用「点拍」，与「拍摄」同义，指日拍摄清单中按拍摄风格统计的拍摄次数） |
| 客资 / 客资数 | 获取的潜在客户数（通过公域内容、私域引流等渠道） |
| 成交金额 | 客户为某次拍摄实际支付的金额 |
| 生命周期阶段 | 爆发期(0-30天) / 稳定期(31-90天) / 衰退期(91-180天) / 长尾期(180天+) |
| 僵尸产品 | 已上架但近30天无点拍记录的产品 |
| 场景拥堵 | 某场景关联产品过多（>10个），但点拍量集中在少数产品（TOP3占比>80%）。关联关系来自执行output表的影棚字段，TOP3按点拍数排名 |
