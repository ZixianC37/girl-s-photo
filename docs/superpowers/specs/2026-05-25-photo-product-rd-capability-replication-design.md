# 写真产品研发能力复制系统设计

## 背景

写真产品研发部门面临核心挑战：高爆款率的资深高手的能力难以复制给新人。同样的 AI 工具，产品经理使用和没有基础的人使用，产出质量差距巨大。差距不在工具本身，而在使用者的认知框架和判断力。

公司已搭建完善的飞书多维表格体系，沉淀了产品数据。本系统旨在通过结构化拆解、知识库建设和工作流引导，将资深高手的爆款研发能力复制给新人，提升整体爆款率。

## 核心场景

- **参考对象**：公司内部有高爆款率的资深产品策划/摄影师，高度配合拆解
- **培养对象（= 使用者）**：新入职或爆款率较低的产品策划/摄影师。本文中"培养对象"、"使用者"、"新人"均指同一角色
- **北极星指标**：爆款率（多维度综合评价，见"成功指标"章节）

## 成功指标

**北极星指标**：爆款率

爆款定义：上线后 90 天内，在多维度综合评价中达到"爆款"标准的产品占比。综合评价维度包括：
- 销售数据（订单量、销售额）
- 客户评价（好评率、NPS）
- 复购率
- 传播效应（社交媒体分享量、自然流量占比）

具体阈值（需与业务方在阶段 1 启动前对齐）：
- 基线：当前团队整体爆款率（通过飞书历史数据计算）
- 阶段 1 目标：培养对象在参考对象评判下，关键决策质量优于无工具辅助时的对照组
- 阶段 2 目标：使用工具的培养对象爆款率较基线提升（具体百分比待基线确定后设定）
- 阶段 3 目标：扩大使用范围后，团队整体爆款率持续提升

## 7 阶段 SOP 框架

工作流引导基于以下 7 阶段 SOP 展开（详细调研提纲见 `docs/写真产品研发SOP调研提纲.md`）：

1. **风格定义与趋势洞察**：趋势信息来源、趋势分析与判断
2. **主题策划与产品定义**：主题创意来源、产品定位、目标客群定义
3. **视觉方案设计**：拍摄方案制定、场景/造型/道具规划
4. **样片拍摄执行**：拍摄团队协调、现场调整、样片筛选
5. **后期制作与交付**：修图标准、交付物规格、质量检查
6. **上市与市场反馈**：上架执行、营销素材、数据监测
7. **复盘与知识沉淀**：产品复盘、经验归档、流程优化

## 前置假设与前提条件

1. 参考对象愿意且能够表达隐性知识（部分直觉型知识可能需要通过对比实验间接提取，而非直接访谈）
2. 飞书多维表格中已有足够结构化的产品数据（至少包含销售量、客户评价、风格标签等基础字段）
3. 7 阶段 SOP 框架已与研发团队对齐（调研提纲已就绪，需完成实际调研）
4. 有 1-2 个培养对象愿意参与阶段 1 试用

## 设计原则

1. **架构-界面分离**：三层能力模型是内部架构，使用者看到的是一个自然的工作流助手
2. **置信度标注**：每条知识标明来源样本量和验证状态，区分"可复制规律"和"可能巧合的模式"
3. **时效性管理**：知识库条目标注时效和最后验证时间，推动定期更新
4. **记录为主评分为辅**：成长追踪以存档为主，避免在创意型工作中过度评分

## 三层能力模型

系统围绕三层能力差距构建：

### 第一层：信息与知识（你知道什么）

参考对象掌握的行业信息源、历史爆款数据、客户偏好规律、供应商资源等。

- 填补方式：结构化知识库 + 飞书数据沉淀 + 爆品归因结论
- 可量化：信息覆盖度

### 第二层：决策与方法（你怎么判断）

参考对象在关键决策节点的判断逻辑、取舍标准、风险嗅觉。

- 填补方式：工作流引导中的"高手视角"嵌入 + 模拟决策对比
- 可量化：决策一致性（新人的选择和高手的重合度）

### 第三层：审美与直觉（你感觉什么好）

参考对象的审美偏好、创意敏感度、客户需求嗅觉。

- 填补方式：实战演练 + 对比反馈 + 大量爆品/非爆品案例浸泡
- 难以直接量化，只能通过结果间接验证

## 数据闭环

系统是一个自我增强的闭环：

```
参考对象拆解 ──→ 能力模型构建
                    │
飞书历史数据 ──→ 知识库填充 ←── 爆品归因分析
                    │
工作流引导 ──→ 新人执行产出
                    │
结果数据回流 ──→ 新一轮归因 ──→ 知识库更新
```

早期依赖参考对象拆解提供基础，后期归因分析占比越来越大。每一轮产品研发的结果都会让系统变得更强。

## 核心模块设计

### 模块 1：拆解引擎（采集参考对象能力）

系统化地提取参考对象的隐性知识，转化为结构化数据。

三种拆解方式：

1. **工作流伴随式拆解**：让参考对象在工具中完成一次完整的产品研发流程，在每个决策节点由工具弹出简短问卷（"你为什么选了这个方向？""你考虑了哪些因素？""排除了哪些备选？"），而非录屏或自动化监控。目的是降低技术复杂度，同时确保采集到决策理由
2. **决策回溯访谈**：拿一个已上线的爆款产品，让参考对象回溯"当时为什么这样做"，记录关键决策点和取舍逻辑
3. **对比实验**：给参考对象和新人同一个任务，对比过程和结果差异，精确定位差距点

产出物：
- 能力项清单（如"风格趋势判断"、"目标客群匹配"等）
- 每个能力项下的决策规则（"当遇到X情况时，高手通常会考虑Y"）
- 典型案例库（高手处理过的真实场景及解决方案）

### 模块 2：知识引擎（结构化储存+检索）

统一存储拆解结果、飞书历史数据、归因结论，在合适时机推送给使用者。

知识条目结构：

```
知识条目 {
  标题: "春季主题的风格趋势判断"
  内容: 具体知识内容
  来源: "参考对象A访谈" | "飞书产品数据归因" | "行业报告"
  适用阶段: "主题策划与产品定义"
  关联能力项: "风格趋势判断"
  置信度: "待验证" | "已验证(基于N个样本)"
  时效: "2026年春季" | "长期有效"
  关联条目: [相关知识条目列表]
}
```

三种检索方式：
- **主动检索**：新人在工作中遇到问题时搜索
- **被动推送**：工作流引导到某个决策节点时，自动推送相关知识
- **知识图谱导航**：通过可视化图谱浏览，发现关联知识

### 模块 3：归因引擎（爆品/非爆品因素分析）

分析每个产品的成功/失败因素，生成"成功配方"和"失败教训"。

数据输入：
- 飞书多维表格中的产品数据（销售量、客户评价、定价、风格标签等）
- 研发过程中的过程数据（决策记录、方案版本、修改原因等）
- 外部环境数据（季节、竞品动态、社交媒体趋势等）

归因方法演进：
- 早期（数据少）：以参考对象的经验判断为主，定性归因
- 中期（有积累）：定量分析产品特征和结果的统计关系
- 成熟期：结合定性定量，形成较可靠的因果推断

产出物：
- 每个产品的归因报告
- 聚合后的"成功模式"和"失败模式"
- 每个因素的置信度和影响力权重

### 模块 4：工作流引导（面向使用者的核心交互）

引导新人按照能力框架完成产品研发，在每个关键节点提供知识支持和决策辅助。

按 7 阶段 SOP（见"7 阶段 SOP 框架"章节）展开，每个阶段包含：
1. **任务清单**：这个阶段要做什么
2. **知识卡片**：做这个任务需要知道什么（来自知识引擎）
3. **决策辅助**：在关键节点展示"高手视角"
4. **自我检查**：完成后的验证清单
5. **存档记录**：记录新人的决策和产出，供后续归因和成长追踪

### 模块 5：成长追踪（轻量培训属性）

记录新人的成长过程，保持克制——记录为主，评分为辅。

包含：
- **能力雷达图**：对照参考对象的能力模型，展示当前状态（来源：自我评估 + 导师评估）
- **决策存档时间线**：记录每个产品研发中的关键决策，不做评分
- **结果关联**：产品上线后，回溯研发决策记录，分析哪些决策可能影响了结果

不包含：
- 复杂的加权评分算法
- 强制排名或与绩效挂钩的评分
- 创意/审美的直接评分

## 风险识别与保护机制

### 行业特殊性风险

写真产品有时机性、地域性、团队执行力和运气成分。拆解过度可能得出"伪因果"。

保护机制：知识库中每条"成功因素"标注置信度，区分"可复制的规律"和"可能是巧合的模式"。

### 归因可靠性风险

样本量有限、多因一果、幸存者偏差。

保护机制：归因结果标注来源（"基于N个样本"）和状态（"已验证"/"待验证"/"有争议"），结论作为"待验证的假设"而非真理注入知识库。

### 参考对象知识衰减风险

行业变化导致拆解结果过时。

保护机制：知识条目加"时效标签"和"最后验证时间"，定期让参考对象 review 已拆解知识的准确性。

### 使用者接受度风险

工具过于教条或有经验的新人感觉被束缚。

保护机制：三层模型是后台架构，使用者界面是自然的工作流助手，在恰当时机给出恰当帮助，不做强制流程。

## 分阶段落地路径

### 阶段 1：基础框架（MVP，约 4-6 周）

目标：验证"拆解→知识库→工作流引导"链路跑通。

范围：
- 选择 1 个参考对象，完成 1-2 个完整产品的决策回溯拆解
- 构建知识引擎的底层数据结构
- 实现 7 阶段工作流引导的基本框架（任务清单 + 知识卡片 + 决策辅助）
- 将飞书中现有的产品数据导入知识库
- 选择 1-2 个培养对象试用

暂不包含：归因引擎、知识图谱可视化、成长追踪模块

验证标准：培养对象能否在工具引导下完成一次完整的产品研发流程，且关键决策质量（由参考对象评判）高于无工具辅助时。

### 阶段 2：数据闭环（MVP 验证后，约 6-8 周）

目标：让闭环运转起来——产品结果回流驱动知识更新。

范围：
- 接入阶段 1 培养对象产出的产品数据，做初步归因分析
- 扩大参考对象拆解范围
- 上线归因引擎的定性分析模式
- 实现知识条目的置信度标注和时效管理
- 增加知识图谱可视化
- 增加成长追踪的基础功能（能力雷达图 + 决策存档）

验证标准：归因引擎产出的"成功模式"是否被参考对象认可；知识库是否能从产品结果数据中自动更新。

### 阶段 3：规模化与智能化（稳定运行后，持续迭代）

目标：扩大使用者范围，提升系统智能程度。

范围：
- 扩大到更多培养对象
- 归因引擎从定性为主过渡到定量为主
- 基于积累的数据训练更精准的"成功预测模型"
- 知识图谱的关联关系更加丰富和准确
- 探索 AI 辅助的决策建议（轻量版）

暂不包含：全自动 AI 产品生成、替代人工的决策系统、对外 SaaS 化（先内部跑通）。

## 技术载体（待定）

先定义清楚拆解框架和能力模型，再根据实际需求决定落地载体（飞书多维表格扩展 / 独立 Web 工具 / 其他形式）。阶段 1 的载体选择将在实施规划阶段确定。

## 系统边界

本系统**不是**：
- HR 绩效管理系统（不与薪酬/晋升挂钩）
- 全自动 AI 产品生成工具（目标是培养人，不是替代人）
- 通用培训平台（专为写真产品研发场景设计）
- 知识管理门户（知识库服务于工作流，不是独立的信息检索系统）
