# 写真产品研发 — 任务分发中台方案汇报材料

---

## 一、我们面临的问题

写真产品研发部门在实际业务中遇到了两个核心痛点：

**第一，任务触达不到位。** 公司虽然有飞书多维表格等业务系统，但很多员工不习惯主动去查看系统通知。一个品鉴会任务发下去，半天没人确认，你不知道大家到底看到没有。

**第二，回收闭环做不到。** 任务分配之后，谁确认了、谁没确认、文件交没交、进度到哪了——这些信息散落在各个群聊和私聊里，需要人工一个个催、一个个问。开一场品鉴会，光收集准备材料就要花大量沟通成本。

根本原因：**员工不愿意学习新的业务系统。** 那与其推着他们去用系统，不如把系统推到他们面前——用他们每天都在用的聊天工具作为任务触达和回收的入口。

---

## 二、解决方案：任务分发中台

我们的方案是构建一个"任务分发中台"，它连接两个系统：

- **飞书多维表格**作为数据层——所有业务数据（任务、人员、状态）在这里统一管理
- **钉钉群聊和单聊**作为触达层——员工不需要打开任何新系统，在钉钉里就能收到任务、确认参加、提交文件

中台服务是连接两者的桥梁，负责：
1. 监听飞书数据变更，自动在钉钉下发任务
2. 接收钉钉中员工的操作（确认、文件提交），回写到飞书
3. 自动跟踪进度，定时催办未完成的人

**核心理念：飞书管数据，钉钉管触达，中台做桥梁。**

---

## 三、为什么选择钉钉

我们对三个主流平台做了完整的技术调研：企业微信、钉钉、个人微信。

### 企业微信

- 优点：微信使用习惯好，员工零学习成本
- 缺点：群聊中机器人不能接收文件上传，只能收文本；消息卡片不支持动态更新（发出去的卡片不能原地改内容）；交互能力弱

### 个人微信

- 微信官方在2026年3月推出了ClawBot插件，但仅支持私聊，不支持群聊交互
- 非官方方案（WeChatFerry等）有封号风险，不适合企业生产环境

### 钉钉（推荐方案）

- **互动卡片**：这是钉钉的核心优势。可以发送带有按钮、表单的交互式卡片消息，用户直接在卡片上操作
- **动态更新**：卡片发出去之后可以原地更新内容（比如进度从"1/8"变成"3/8"），不需要重新发消息
- **文件接收**：单聊中支持接收文件、图片、视频
- **按钮回调**：用户点击按钮（如"确认参加"），钉钉会把点击事件回调到我们的服务器，我们就能自动处理

钉钉的互动卡片让我们能实现最接近原生应用的交互体验，而不需要员工安装任何新软件。

## 五、完整场景模拟：品鉴会任务全流程

以下是"5月竞品写真品鉴会"从创建到完成的完整模拟。

### 第1步：管理员在飞书创建任务

管理员打开飞书多维表格，在"任务表"中新增一条记录：

| 字段 | 填写内容 |
|---|---|
| 任务标题 | 5月竞品写真品鉴会 |
| 任务类型 | 品鉴会 |
| 描述 | 本周五举行竞品写真品鉴会，请每位参会人准备3套市面竞品写真的样片和分析笔记 |
| 参会人 | 张三、李四、王五、赵六、孙七 |
| 截止时间 | 2026年6月12日 18:00 |
| 目标钉钉群 | 产品研发群 |

填好保存。飞书自动化触发webhook，通知中台。

### 第2步：中台自动在钉钉群下发任务（几秒内完成）

中台收到webhook后：
1. 解析任务数据（标题、参会人、截止时间等）
2. 将飞书用户ID映射为钉钉用户ID
3. 在"产品研发群"发送互动卡片，@所有参会人

群里的员工立刻看到一张精美的任务卡片，上面有品鉴会详情和"确认参加"按钮。

### 第3步：员工在群里确认

张三在群里看到卡片，点击"确认参加"：
- 钉钉回调中台
- 中台更新卡片：张三状态变为"已确认 ✓"
- 中台回写飞书：张三的提交记录状态更新为"已确认"
- 中台自动私聊张三："请在本对话中发送你的品鉴会准备材料（竞品样片和分析笔记）"

李四、王五陆续也点了确认。每确认一人，群里的卡片自动刷新显示最新进度。

### 第4步：员工在单聊中提交文件

张三在钉钉上看到机器人的私聊消息，直接在对话中发送了3张竞品写真样片的图片和一份分析笔记文档。

中台收到文件回调：
1. 自动下载文件
2. 存储到云端（OSS）
3. 生成文件访问链接
4. 回写飞书多维表：在张三的提交记录中添加文件链接
5. 群里的卡片更新："张三已提交 ✓"

其他员工也陆续在私聊中提交了材料。每提交一人，群卡片实时刷新。

### 第5步：自动催办（无需人工干预）

6月10日（截止时间前2天），中台检测到：
- 王五：已确认但未提交文件 → 私聊提醒"距离截止还有2天，请尽快提交准备材料"
- 赵六：未确认 → 私聊提醒"你有一个品鉴会任务待确认"

6月11日（截止前1天）：
- 赵六仍未确认 → 在群里@赵六 "距截止仅剩1天，请尽快确认"

6月12日（截止日）：
- 孙七逾期未提交 → 通知管理员（升级）"孙七未在截止时间内提交品鉴会材料"
- 孙七后来提交了 → 系统正常接收，但标记为"逾期提交"

### 第6步：任务完成

6月12日下午，最后一份材料提交完毕：
- 群里卡片更新为"✅ 全部完成"状态
- 飞书多维表任务状态更新为"已完成"
- 管理员在飞书中可以直接看到每个人的提交记录和文件链接

**整个过程，管理员只做了一件事：在飞书里填了一行表格。剩下的确认、收集、催办、进度更新全部自动完成。**

## 六、系统架构概览

```
管理员在飞书填表 → 飞书自动通知中台 → 中台在钉钉群发互动卡片
                                          ↓
员工点确认/发文件 → 钉钉回调中台 → 中台回写飞书 + 更新卡片
                                          ↓
中台定时检查 → 发现逾期 → 自动催办（群@/私聊/升级通知）
```

三层架构：
- **数据层（飞书多维表）**：业务主数据，所有任务的唯一真相源
- **中台服务**：事件路由、身份映射、任务引擎、文件管理、催办调度
- **触达层（钉钉）**：群聊互动卡片（任务下发+进度展示）+ 单聊（文件收集）

## 七、关键数据

### 平台能力对比

| 能力 | 钉钉 | 企业微信 | 个人微信 |
|---|---|---|---|
| 互动卡片（按钮/表单） | 支持 | 弱 | 不支持 |
| 卡片原地动态更新 | 支持 | 不支持 | 不支持 |
| 群内@指定人 | 支持 | 支持 | 不支持 |
| 群内文件接收 | 不支持 | 不支持 | 不支持 |
| 单聊文件接收 | 支持 | 支持 | 仅私聊 |
| API成熟度 | 高 | 高 | Beta |

### 技术限制

- 钉钉自定义机器人发送频率：20条/分钟（需队列控制批量下发）
- 钉钉标准版API额度：10,000次/月（可能需升级专业版9,800元/年）
- 群聊文件收集：所有平台都不支持，必须走单聊

## 八、扩展可能性

这个中台架构是通用的，品鉴会只是第一个场景。后续可以扩展到：

1. **产品研发SOP各阶段任务**：样片评审、上市准备等关键节点自动下发
2. **钉钉OA反向集成**：外出拍摄审批单自动同步到飞书多维表
3. **更多触达渠道**：如果未来需要，可以扩展企业微信通道（架构已预留）

每个新场景只需要：在飞书配置对应的表格字段 + 在中台配置路由规则，不需要重新开发核心组件。
