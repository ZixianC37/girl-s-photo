# 飞书 + 业务中台驱动钉钉任务

## 架构概览

```
┌──────────────────────────────────────────────────────────┐
│                      钉钉（任务执行层）                    │
│     工作流引导 · 任务推送 · 决策节点提醒 · 反馈采集        │
├──────────────────────────────────────────────────────────┤
│                    业务中台（能力引擎层）                   │
│  拆解引擎 · 知识引擎 · 归因引擎 · 工作流引擎 · 成长追踪    │
├──────────────────────────────────────────────────────────┤
│                  飞书多维表格（数据层）                    │
│    产品数据 · 历史爆款数据 · 研发过程记录 · 归因结果        │
└──────────────────────────────────────────────────────────┘
```

## 三层架构定位

### 飞书多维表格 — 数据层

**角色**：企业已有的结构化数据沉淀中心

**承载内容**：
- 产品数据（名称、风格标签、定价、季节标签）
- 销售数据（订单量、销售额、客户评价）
- 研发过程记录（策划方案、决策记录、方案版本）
- 爆品归因结果（成功因素、失败教训、置信度）
- 知识库条目（蒸馏后的结构化知识）

**优势**：
- 公司已搭建完善的多维表格体系
- 数据格式结构化，便于程序化读取
- 团队已有使用习惯，无需额外培训数据录入

### 业务中台 — 能力引擎层

**角色**：核心逻辑处理层，连接数据和使用者

**五大模块**：

| 模块 | 职责 |
|------|------|
| 拆解引擎 | 从参考对象采集隐性知识，转化为结构化数据 |
| 知识引擎 | 统一存储和检索知识条目，在合适时机推送 |
| 归因引擎 | 分析爆品/非爆品的成功/失败因素 |
| 工作流引擎 | 按 7 阶段 SOP 引导产品研发流程 |
| 成长追踪 | 记录培养对象的决策存档和能力变化 |

### 钉钉 — 任务执行层

**角色**：使用者日常接触的交互界面

**承载功能**：
- 工作流引导（任务清单、知识卡片、决策辅助）
- 任务推送（关键节点的提醒和引导）
- 决策采集（工作流伴随式拆解的问卷入口）
- 反馈收集（培养对象的自我检查和决策记录）

**选择钉钉的原因**：
- 团队日常工作在钉钉完成，无需切换工具
- 钉钉任务/审批/消息等能力可作为工作流载体
- 降低使用者学习成本

## 数据流

```
飞书数据 ──读取──→ 业务中台（知识引擎/归因引擎）
                         │
参考对象拆解 ──写入──→ 飞书知识库表格
                         │
业务中台 ──推送──→ 钉钉任务/消息
                         │
培养对象操作 ──记录──→ 业务中台 ──写入──→ 飞书过程记录表格
                         │
产品上线结果 ──回流──→ 飞书销售数据 ──触发──→ 归因引擎
```

## 7 阶段 SOP 工作流

工作流引擎基于以下 7 个阶段引导产品研发：

| 阶段 | 核心任务 | 关键决策点 |
|------|---------|-----------|
| 1. 风格定义与趋势洞察 | 趋势信息收集、趋势分析判断 | 趋势判断、风格方向确定 |
| 2. 主题策划与产品定义 | 主题创意、拍摄方案、定价 | 主题选择、定位、定价策略 |
| 3. 视觉方案设计 | 妆面造型、服装搭配、场景设计 | 视觉基调、方案评审 |
| 4. 样片拍摄执行 | 拍摄准备、现场执行、质量把控 | 拍摄方案调整、样片筛选 |
| 5. 后期制作与交付 | 选片、精修、归档 | 修图标准、成品输出 |
| 6. 上市与市场反馈 | 上线推广、销售监测、客户反馈 | 推广策略、反馈响应 |
| 7. 复盘与知识沉淀 | 产品复盘、经验沉淀 | 归因分析、知识归档 |

每个阶段在工作流中包含：
1. **任务清单** — 这个阶段要做什么
2. **知识卡片** — 需要知道什么（来自知识引擎）
3. **决策辅助** — 关键节点的"高手视角"
4. **自我检查** — 完成后的验证清单
5. **存档记录** — 记录决策和产出

## 工作流伴随式拆解

当参考对象（而非培养对象）使用工具时，工作流引擎启用"拆解模式"：

- 每个决策节点弹出简短问卷
- 采集参考对象的决策理由
- 采集到的回答自动转化为知识条目
- 知识条目写入飞书知识库表格
- 同时供培养对象后续查阅

## 闭环运转

```
产品上线 → 飞书销售数据更新 → 归因引擎分析
    → 成功/失败因素写入知识库 → 下次工作流引导时推送
    → 培养对象获得更精准的决策辅助
```

系统越用越强：早期依赖参考对象拆解，后期归因分析占比越来越大。
