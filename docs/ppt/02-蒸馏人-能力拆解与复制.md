# 蒸馏人 — 能力拆解与复制框架

## 什么是"蒸馏人"

将资深高手的爆款研发能力进行系统化拆解，提炼出可传授、可复制的结构化知识，通过工具将这些"蒸馏"出来的能力传递给新人，帮助其成长。

"蒸馏"一词强调的是：不是照搬高手的全部经验，而是**提取出可结构化、可传授的核心能力要素**。

## 为什么需要蒸馏

- 写真行业的爆款能力高度依赖隐性知识（审美、直觉、经验判断）
- 传统的"师傅带徒弟"模式效率低、不可规模化
- 同样的 AI 工具，不同认知框架的人使用效果天差地别
- 公司需要系统化的方法来提升新人成长速度

## 拆解方法

### 方法一：工作流伴随式拆解

让参考对象在工具中完成一次完整的产品研发流程，在每个决策节点由工具弹出简短问卷：
- "你为什么选了这个方向？"
- "你考虑了哪些因素？"
- "你排除了哪些备选？"

目的：在高手工作的自然流程中采集决策理由，降低技术复杂度。

### 方法二：决策回溯访谈

拿一个已上线的爆款产品和一个非爆款产品，让参考对象回溯"当时为什么这样做"，记录关键决策点和取舍逻辑。

访谈结构（每个产品约 90 分钟）：
1. **整体回溯**（20 分钟）：从构思到上线的全过程
2. **逐阶段决策回溯**（50 分钟）：7 个阶段的关键决策
3. **隐性知识探索**（20 分钟）：哪些是"就是知道该这样做"的直觉型决策

每个决策点评判**可表达性**（1-5 分）：
- 5 分：能清晰说明原因和逻辑
- 3 分：能说一些，但很多凭直觉
- 1 分：完全凭直觉，无法解释原因

### 方法三：对比实验

给参考对象和培养对象同一个任务（如"策划一个夏季写真主题"），对比全过程的决策差异。

对比维度：
1. **信息获取**：信息量、信息源数量、信息质量差异
2. **决策过程**：决策节点覆盖度、考虑因素全面性、备选方案数量
3. **产出质量**：最终方案由参考对象盲评
4. **过程效率**：各步骤耗时对比
5. **卡点差异**：各自遇到的困难和解决方式

## 拆解产出物

| 产出物 | 说明 |
|--------|------|
| 能力项清单 | 如"风格趋势判断"、"目标客群匹配"、"定价策略"等 |
| 决策规则 | "当遇到 X 情况时，高手通常会考虑 Y" |
| 典型案例库 | 高手处理过的真实场景及解决方案 |
| 差距图谱 | 高手与新人在各能力项上的具体差距 |

## 三层差距与对应填补策略

### 信息与知识层 — "你知道什么"

差距表现：高手掌握的行业信息源、历史爆款数据、客户偏好规律，新人不知道。

填补策略：
- 结构化知识库系统化存储这些信息
- 飞书历史产品数据导入作为知识来源
- 爆品归因结论转化为可查阅的知识条目

### 决策与方法层 — "你怎么判断"

差距表现：面对同样的信息，高手和新人的判断逻辑不同。

填补策略：
- 工作流引导中嵌入"高手视角"
- 关键决策节点展示"在这种情况下，XX 通常会考虑..."
- 模拟决策对比：新人做完选择后展示高手的选择和理由

### 审美与直觉层 — "你感觉什么好"

差距表现：高手的审美偏好、创意敏感度、客户需求嗅觉。

填补策略：
- 实战演练 + 对比反馈
- 大量爆品/非爆品案例浸泡
- 记录新人的每次审美判断，对比高手的选择，形成渐进式训练

## 知识条目结构

每条"蒸馏"出来的知识都按统一结构存储：

```
知识条目 {
  标题: "春季主题的风格趋势判断"
  内容: 具体知识内容
  来源: "参考对象A访谈" | "飞书产品数据归因" | "行业报告"
  适用阶段: "主题策划与产品定义"
  关联能力项: "风格趋势判断"
  置信度: "待验证" | "已验证(基于N个样本)"
  时效: "2026年春季" | "长期有效"
}
```

置信度标注是关键：区分"可复制的规律"和"可能是巧合的模式"，避免把运气当方法论。

## 蒸馏的局限性

- 部分隐性知识可能**无法被显性化**（直觉型审美判断）
- 行业在变化，拆解结果是**某个时间点的快照**，需要定期更新
- 写真产品的成功有时机性、地域性、运气成分，**不是所有成功都可以复制**
- 归因分析面临**样本量有限、多因一果、幸存者偏差**的问题

应对：每条知识标注置信度和时效，作为"待验证的假设"而非真理。
