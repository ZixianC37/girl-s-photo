# RAG对比测试

## 输入
- 已构建的GraphRAG系统
- 传统RAG系统（仅向量检索）
- 测试问题集（至少5个多跳问题）

## 输出
- 测试问题集文档
- GraphRAG测试结果
- 传统RAG测试结果
- 对比分析报告
- 性能优化建议

## 执行步骤
1. **创建测试问题集**
   - 设计至少5个多跳问题，覆盖以下类型：
     - 单实体查询："客户张三的电话号码是多少？"
     - 关系查询："客户张三下过哪些订单？"
     - 多跳查询："客户张三购买的'个人写真'产品是由哪位摄影师负责的？"
     - 聚合查询："客户张三的总消费金额是多少？"
     - 复杂查询："2024年1月由'李摄影师'负责拍摄且金额超过5000元的订单有哪些？"
   - 为每个问题准备标准答案
   - 难度分级：简单、中等、困难

2. **设置传统RAG基线**
   - 使用纯向量检索（Chroma）
   - 相同的嵌入模型：`SentenceTransformer('paraphrase-multilingual-MiniLM-L12-v2')`
   - 相同的LLM：Claude 3.5 Sonnet
   - 相同的Prompt模板
   - 确保只有检索方式不同（GraphRAG vs VectorRAG）

3. **执行GraphRAG测试**
   - 根据`/Users/chenzixian/Downloads/写真行业/RAG/docs/knowledge/03-practical-steps.md`步骤7.3-7.4，执行混合检索：
     - 图检索：使用Cypher查询图谱
     - 向量检索：使用Chroma检索文档
     - 结果合并：按权重合并（图0.6，向量0.4）
     - 答案生成：调用Claude API
   - 记录每个问题的：
     - 检索时间（ms）
     - 生成时间（ms）
     - 总响应时间（ms）
     - 检索到的实体/文档数量
     - 生成的答案

4. **执行传统RAG测试**
   - 使用纯向量检索：
     - 向量检索：使用Chroma检索文档（top_k=10）
     - 答案生成：调用Claude API
   - 记录每个问题的：
     - 检索时间（ms）
     - 生成时间（ms）
     - 总响应时间（ms）
     - 检索到的文档数量
     - 生成的答案

5. **评估指标计算**
   - **准确性**：答案与标准答案的匹配度
     - 完全匹配：1分
     - 部分匹配：0.5分
     - 不匹配：0分
   - **完整性**：答案是否包含所有关键信息
     - 完全包含：1分
     - 部分包含：0.5分
     - 缺失：0分
   - **可解释性**：答案是否提供推理过程
     - 提供推理过程：1分
     - 部分提供：0.5分
     - 无推理过程：0分
   - **延迟**：总响应时间（ms）

6. **对比分析**
   - 按问题难度对比：
     - 简单问题：GraphRAG vs 传统RAG
     - 中等问题：GraphRAG vs 传统RAG
     - 困难问题：GraphRAG vs 传统RAG
   - 按问题类型对比：
     - 单实体查询：GraphRAG vs 传统RAG
     - 关系查询：GraphRAG vs 传统RAG
     - 多跳查询：GraphRAG vs 传统RAG
     - 聚合查询：GraphRAG vs 传统RAG
     - 复杂查询：GraphRAG vs 传统RAG
   - 整体性能对比：
     - 平均准确率：GraphRAG vs 传统RAG
     - 平均完整性：GraphRAG vs 传统RAG
     - 平均可解释性：GraphRAG vs 传统RAG
     - 平均延迟：GraphRAG vs 传统RAG

7. **生成对比报告**
   - 报告结构：
     - 测试概述（问题数量、类型、难度）
     - 测试环境（硬件、软件配置）
     - GraphRAG结果（每个问题的详细结果）
     - 传统RAG结果（每个问题的详细结果）
     - 对比分析（按难度、类型、整体）
     - 结论（GraphRAG的优势和劣势）
     - 优化建议（如何提升GraphRAG性能）
   - 使用Markdown格式，包含表格和图表

8. **性能优化建议**
   - 根据`/Users/chenzixian/Downloads/写真行业/RAG/docs/knowledge/04-pitfalls-best-practices.md`，提供优化建议：
     - 查询优化：创建索引、使用LIMIT、避免全表扫描
     - 检索优化：调整权重、增加检索深度、优化嵌入模型
     - 上下文优化：优化上下文构建、增加相关信息、压缩上下文
     - LLM优化：优化Prompt、使用更快的模型、增加缓存

## 质量验收标准
- 测试问题数量：>=5个多跳问题
- 测试覆盖度：覆盖所有问题类型（单实体、关系、多跳、聚合、复杂）
- 测试重复性：每个问题测试3次，取平均值
- 报告完整性：包含所有测试结果、对比分析、结论、建议
- 报告可读性：使用表格和图表，结构清晰，易于理解

## 常见问题
- **问题1：GraphRAG性能不如传统RAG**
  - 现象：在某些简单问题上，GraphRAG的响应时间比传统RAG长
  - 解决：优化图检索（创建索引、使用参数化查询），调整混合权重（减少图检索权重）
  - 参考：`/Users/chenzixian/Downloads/写真行业/RAG/docs/knowledge/04-pitfalls-best-practices.md`第3节"查询优化问题"

- **问题2：测试问题不够全面**
  - 现象：测试问题只覆盖了部分场景，无法全面评估系统性能
  - 解决：增加问题数量（至少10个），覆盖更多问题类型（统计、比较、推荐），增加边缘案例（空结果、模糊查询）
  - 参考：`03-practical-steps.md`步骤7.1-7.4

- **问题3：评估标准不客观**
  - 现象：人工评估存在主观性，影响结果可靠性
  - 解决：使用多个评估者（至少2个），制定明确的评分标准，使用自动化评估工具（如BLEU、ROUGE）
  - 参考：无，这是测试设计问题

- **问题4：性能波动大**
  - 现象：同一问题的响应时间波动较大，影响结果可靠性
  - 解决：多次测试（至少3次），取平均值，排除异常值，在相同环境下测试
  - 参考：无，这是测试设计问题

- **问题5：对比报告不清晰**
  - 现象：对比报告数据杂乱，难以得出结论
  - 解决：使用表格和图表，按维度对比（难度、类型、整体），提供明确的结论和建议
  - 参考：无，这是报告设计问题
